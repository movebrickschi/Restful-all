## 1. 产品背景

### 1.1 v1.2 现状（参考 `docs/features.md`）

v1.2 已交付的能力可归纳为「**5 框架 × 路由扫描 + 轻量调试**」：

- 自动扫描 Spring / NestJS / Express / FastAPI / Flask 五大框架的 REST 路由
- 路由列表 + `Ctrl+Alt+/` 搜索弹窗 + 双击跳源码
- 「接口」标签页含基础 API 调试面板（GET/POST/...，Query/Body/Path/Headers/Cookies）
- 全局参数、前置 URL（多模块）、请求历史（最多 500 条）
- 4 个工具窗口标签页持久化到 `.idea/restful-all.xml`

### 1.2 痛点：用户为什么跳到 Postman

我们观察 / 推测的 7 类典型痛点：

| # | 痛点 | 典型场景 |
| - | --- | --- |
| 1 | 没有环境变量，dev / test / prod 切换靠手改 URL | 测完 dev 又复制 URL 改 host 测 test |
| 2 | 不能 import cURL / Swagger / Postman Collection | 后端给的 Swagger / 同事的 cURL 一行就回 Postman |
| 3 | 没有 Auth 模板（Basic / Bearer / API Key） | 调有鉴权的接口要手动塞 Header |
| 4 | 响应只能看 raw JSON，不能 JSON Path 提取 / 表格视图 / 下图 | 调返二进制 / 大数组的接口体验差 |
| 5 | 没有断言，无法验"返回 status=200 且 data.id 存在" | 回归只能眼睛瞄 |
| 6 | 历史只有列表，没有搜索 / 标签 / 导出 | 找昨天那个请求只能翻 500 条 |
| 7 | 多人 / 多端配置无法共享 | 自己的 collection / env 换电脑就丢 |

### 1.3 商业机会：Pro 价值在哪

免费档**必须先达到 Postman free 90% 体验**，否则用户跳不回插件；Pro/Team 档**必须有 Postman 收费版做不到的差异化**才有付费理由：

| Pro 差异化 | 形态 |
| --- | --- |
| AI 智能参数填充 / 接口诊断 / 用例生成 | IDE 内零跳转，比独立 Postman AI 体验顺 |
| Workspace 云同步 / 团队共享 collection | 解决"多端 + 多人"协作 |
| 内置 Mock Server + 文档双向同步 | 后端没好接口前前端就能联调 |
| 接口压测 / 用例编排 / 环境 diff / 签名插件 | 高阶工程化能力 |

### 1.4 v1.3 一句话定位

> **在 IDE 内完整替代 Postman 免费版，并通过 AI + 团队协作建立 Pro / Team 档位的差异化付费价值。**

5. **Day 7 团队协作**：自己 collection 同步到 Workspace（**P1-4**） → 同事打开 IDE 直接复用

## 6. 详细功能 PRD

> 每个功能采用统一模板：**用户故事 / 核心交互 / 约束 / 数据契约 / 验收标准**。

### 6.1 v1.3.0：基础拉新 + 骨架（5 + 4 个）

#### F1 环境变量管理

- **用户故事**：作为 Alice，我要在 dev/test/prod 三个环境间一键切换 URL / Token / DB host，以便不再手改 URL 来回测。
- **核心交互**：
  1. 新增"环境"标签页（与"前置 URL"并列）
  2. 表格：环境名 + 变量列表（key / value / secret / desc）
  3. 顶部下拉框选当前环境，所有调试面板的 `${var}` 即时替换为该环境的值
  4. 密文变量值显示 `••••••`，编辑时弹独立输入框
- **约束**：
  - 变量名格式 `[A-Za-z_][A-Za-z0-9_]*`
  - 单环境变量上限 200 个（防滥用）
  - 加密变量走 IntelliJ `PasswordSafe`（macOS Keychain / Win Credential Manager）
- **数据契约**：见 §8.1 `EnvironmentService`
- **验收**：① 切环境后 URL / Header 中 `${var}` 即时刷新；② 重启 IDE 后明文变量保留、密文走 PasswordSafe；③ 缺失变量发送时高亮 + 阻断；④ 单元测试覆盖循环引用 / 缺失 / 多层嵌套场景

#### F2 cURL 双向转换

- **用户故事**：作为 Alice，我从同事粘来一行 `curl ...`，要能一键导入成调试面板的请求；反之我把当前请求复制成 cURL 命令发给运维。
- **核心交互**：
  1. 调试面板顶部加两个按钮："从 cURL 导入" / "复制为 cURL"
  2. 导入：弹文本输入框 → 解析 → 填到方法 / URL / Headers / Body
  3. 导出：直接 `cmd+c` 到剪贴板，弹 toast"已复制 cURL"
- **约束**：
  - 支持 `-X / --request`、`-H / --header`、`-d / --data / --data-raw / --data-binary`、`-F / --form`、`-u / --user`、`-b / --cookie`、`--compressed`、`--insecure`
  - 解析失败给明确错误位置（高亮失败的 token）
- **数据契约**：纯前端转换，无持久化
- **验收**：① 导入 50+ 真实 cURL 样本通过率 ≥ 95%；② 导出后 `curl` 命令能直接在终端跑通

#### F5 鉴权模板

- **用户故事**：作为 Alice，我要在调试面板选"Bearer Token"输入 token，自动加 `Authorization: Bearer xxx`，不用手敲 Header。
- **核心交互**：
  1. 调试面板新增"Auth"标签页
  2. 类型下拉：None / Basic / Bearer / API Key
  3. Basic：username + password（password 走 PasswordSafe）
  4. Bearer：token（走 PasswordSafe）
  5. API Key：key 名 + value + 放在 Header / Query / Cookie
  6. 发送时自动注入到对应位置（**不持久化到 Headers 表格**，避免泄露明文）
- **约束**：Auth 配置可在环境中作为变量（F1 联动），如 `Bearer ${api_token}`
- **验收**：① 4 种模板都能正确生成请求；② 切环境后 token 自动变；③ 密文不出现在 `.idea/restful-all.xml`

#### F8 内置变量

- **用户故事**：作为 Alice，我要在 Body 写 `{"requestId": "${random.uuid}", "timestamp": ${timestamp}}`，每次发送自动替换。
- **核心交互**：发送前 `${...}` 替换；不持久化（每次发送实时生成）
- **支持变量**：
  ```
  ${random.uuid}        UUID v4
  ${random.int(1,100)}  随机整数
  ${random.string(10)}  随机字母数字串
  ${timestamp}          秒级
  ${timestamp.ms}       毫秒级
  ${date('yyyy-MM-dd')} 格式化日期
  ${env.<key>}          环境变量（与 F1 一致语法）
  ```
- **验收**：在 URL / Query / Body / Headers 任一处都能用；预览面板可展开看替换后值

#### F11 多语言扩展

- **用户故事**：作为海外用户，我要看到英文 UI；社区可贡献 JP / KR 翻译。
- **核心交互**：
  1. Settings → Appearance → Language 下拉（跟随 IDE 语言或手动覆盖）
  2. 现有中文 bundle 全量翻译到英文（**v1.3.0 必出英文**）
  3. JP / KR 提供骨架文件 + 占位中文，社区 PR 补
- **约束**：所有硬编码字符串迁移到 `MyMessageBundle`（已存在）；新字符串必须 i18n
- **验收**：英文 UI 无中文残留（grep 检查）；JP / KR 骨架文件 ≥ 50% key 占位

### 6.2 v1.3.1：AI 首领 + 迁移护航（4 个）

#### F3 Collection 集合组织

- **用户故事**：作为 Alice，我要把"用户中心相关 20 个接口"放进一个 Collection 分组管理，并能拖拽排序。
- **核心交互**：
  1. 路由列表上方新增"我的 Collection"树形面板
  2. 右键路由 → "加入 Collection..." → 选已有或新建
  3. Collection 内的接口可重排、可独立改名（不影响源码路由名）
- **数据**：见 §8.2 `CollectionService`
- **验收**：① 100 个接口的 collection 不卡顿；② 删除源码路由后 collection 内对应项标灰 + 提示

#### F4 Swagger / OpenAPI 导入

- **用户故事**：作为 Alice，我从同事拿到 `swagger.yaml`，一键导入生成完整 collection。
- **核心交互**：
  1. 入口"导入" → 选文件 / 粘 URL / 粘 JSON 文本
  2. 解析后预览树（按 tag 分组）+ 多选导入
  3. 导入后变量（path/query/body）自动填充示例值
- **约束**：支持 OpenAPI 3.0 + 2.0 (Swagger 2)；JSON + YAML 双格式
- **验收**：导入 Petstore + 3 个真实业务 swagger 成功率 100%

#### F12 Postman / Apifox Collection 导入

- **用户故事**：作为从 Postman 迁移过来的 Alice，我要导入我的 Postman v2.1 / v2.0 collection（含变量、auth、scripts）。
- **核心交互**：选文件 → 预览 → 导入；Postman 的 pre-request / test 脚本仅展示原文（v1.3 不执行）
- **支持范围**：
  - Postman Collection v2.1 / v2.0 ✅
  - Postman Environment ✅（→ 转 F1 环境）
  - Apifox 导出格式 ✅
  - Postman scripts ⚠ 仅展示
- **验收**：导入官方 Postman Echo / GitHub API collection 完整可用

#### P0-1 AI 智能参数填充（Pro）

- **用户故事**：作为 Alice 调"创建订单"接口，AI 看了 Swagger 描述自动给我生成合理参数（不再用全 0 / 全 ""）。
- **核心交互**：
  1. Body 编辑器右上角"AI 填充"按钮（Free 用户置灰 + 升级提示）
  2. 调 LLM API（GPT-4o-mini / Claude Haiku） → 流式返回 → 写入 Body
  3. 用户可"再生一个"或"接受"
- **约束**：
  - Pro 用户用平台 API Key（计费走平台）；可选用户自带 Key
  - Free 用户每日 5 次试用
  - 提示词包含：接口注释 / 字段类型 / 已有变量上下文
- **数据**：见 §8.3 `AiService` + `AiUsageQuota`
- **验收**：① 在 50 个真实业务接口上人工评估"参数合理性" ≥ 80%；② 错误率 < 5%（key 失效 / 限流）；③ Free 用户超限正确显示升级弹窗

### 6.3 v1.3.2：接口测试走向专业（6 个）

#### F6 响应高级查看

- **用户故事**：作为 Alice 调返回大 JSON / 图片 / 二进制的接口，我要能切换不同视图查看。
- **核心交互**：响应面板 Body 上方加视图切换：
  - **Pretty**：当前格式化 JSON（默认）
  - **Raw**：原始字符串
  - **Tree**：可折叠的 JSON 树（点击节点复制 JSONPath）
  - **Table**：数组类响应自动转表格（列名取 keys）
  - **Image**：响应 Content-Type 是 image/* 时直接渲染
  - **Download**：响应是 binary / file 时"另存为"
- **验收**：6 种视图都能正确识别 Content-Type 自动切换

#### F7 JSON Path 基础断言

- **用户故事**：作为 Alice，调"用户列表"接口后我要断言"status 是 200 且 data.users.length > 0 且 data.users[0].id 存在"。
- **核心交互**：
  1. 调试面板新增"断言"标签页
  2. 每条断言：JSONPath + 操作符（== / != / > / < / exists / regex）+ 期望值
  3. 发送后右上角绿色 ✓ / 红色 ✗ + 详细失败原因
- **约束**：支持 `$.data.users[0].id` 标准语法 + `$.headers['X-Total']`
- **验收**：8 类操作符在 30 个真实样本上准确率 100%

#### F9 历史标签 + 搜索 + 导出

- **用户故事**：作为 Alice，我要给昨天那个失败的接口打标签"线上 bug"，方便明天回看；并能导出全部历史为 JSON 备份。
- **核心交互**：
  1. 历史条目右键 → "添加标签..." / "添加备注"
  2. 顶部搜索升级为多条件：URL / 标签 / 状态码 / 日期范围

@State(name = "RestfulAll.Environments",
